## 0. 사용자 요구 (그대로)

1. "침로를 모르는 배는 **선수 방향을 기본**으로" — 원형 점을 없앤다.
2. "다른 해양 관련 웹페이지를 참고해서 **처음 보는 사람도 잘 판별**할 수 있게" — 화면이 난잡하다.
3. "**위협 등급·선박 목록은 잘 만들어졌다**" → 내용은 유지하고 자리만 옮긴다.
4. "**토폴로지는 뭔지 하나도 모르겠다**" → 선버스트·생키를 없애고 같은 숫자를 쉬운 그림으로.
5. "**한 화면에 다 담으려 하지 말 것**" → 메뉴로 화면을 나눈다.
6. 해안국 관리자가 쓴다고 생각하고 만든다. 읽기 전용. 1차의 기능(소스 2개·기간/시점·판정기·정답 보기·등고선·원인 카드·항적·실시간 확장 자리)은 **하나도 빠지지 않는다** — 자리만 바뀐다.

## 1. 참고한 구성 (코디네이터가 확인한 것 — 그대로 따른다)

| 참고 | 가져오는 패턴 |
|---|---|
| MarineTraffic Live Map (Kpler 도움말 "Live Map Toolbar"·"Vessel Filters"·"Map layers"·"Vessel InfoWindow") | **지도가 화면 전체**. 검색·필터·레이어·재생(Playback)은 지도 가장자리의 **네모 아이콘 하나씩**이고 누르면 펼쳐진다. 배를 누르면 **옆 패널**에 상세(속력·침로·마지막 보고·항적). 아이콘 **색 = 분류, 방향 = 침로**. 필터는 종류·상태(항해 중/정박)를 **조합**. |
| VesselFinder | 같은 패턴. 상세는 오른쪽 카드, 목록은 별도 화면. 범례는 접혀 있음. |
| 해양수산부 GICOMS(해양안전종합정보시스템) 모바일 | 메뉴가 **"선박 모니터링" · "항적 조회"** 처럼 **동사 하나짜리 이름**. 통계와 지도를 한 화면에 섞지 않음. |

적용 원칙 네 줄:
- **화면 하나 = 질문 하나.** "지금 급한 배가 몇 척?" "어디 있나?" "어느 배?" "어디서 얼마나 들어오나?" "전파 상태는?"
- 지도 화면에서는 **지도 말고는 전부 접힌다.**
- 전문 용어(코드명·dB·잔차)는 **옆에 한 줄 설명**, 숫자는 **단위**와 함께. 큰 숫자가 먼저, 표는 그다음.
- 그래프는 **가로 막대·숫자 타일**만 쓴다. 선버스트·생키·레이더 금지.

## 2. 화면 구조 — 상단 메뉴 5개 + 공통 조건 띠

해시 라우터(`#/overview` `#/map` `#/ships` `#/ship/<mmsi>` `#/flow` `#/signal`)로 한 `index.html` 안에서 화면을 바꾼다(새 파일로 나눠도 됨).
조건(데이터 소스·기간·판정기·정답 보기)은 **URL 해시 질의**에 넣어 화면을 옮겨도 유지된다. 시점(슬라이더)은 지도 화면에만.

**공통 상단 띠**(얇게 한 줄): 왼쪽 이름 "해안국 관리자 화면" · 메뉴 5개(① 상황판 ② 지도 ③ 선박 목록 ④ 수신 현황 ⑤ 신호 품질) · 오른쪽에 **조건 버튼 하나**("부산 실해역 · 06-09 17:56 ~ 06-10 08:30 · 룰") → 누르면 팝오버에 소스·기간·판정기·정답 보기. 지금처럼 띠에 다 펼쳐 두지 않는다.

### ① 상황판 `#/overview` (첫 화면)
- 맨 위 **한 문장**: "지금 기간에 650척 중 **즉시 확인 12척**, 확인 필요 289척, 참고 237척, 보류 13척입니다." (숫자는 API)
- **숫자 타일 4장**(즉시 확인 H · 확인 필요 M · 참고 L · 보류) — 색은 `static/icons/mapping.json` 의 아이콘 색과 같게(빨강·노랑·파랑·분홍). 타일 클릭 → ③ 목록으로 그 등급 필터.
- **지금 봐야 할 배 5척**(영향 H → 위협 → 비정상 비율 순): MMSI · 등급 배지 · 대표 코드 **+ 한 줄 설명** · 마지막 보고. 행 클릭 → `#/ship/<mmsi>`.
- **작은 지도**(상호작용 없음, 배 점만, 클릭하면 ② 로) + 해안국 요약 1줄(받은 메시지 n건 · 비정상 n% · 신호 종합 3단계).
- 위협 1~5 카드는 **여기서 5장 가로로** 1차 내용 그대로(배 수·비정상 행·코드 수·"탐지기 미구현" 표시).

### ② 지도 `#/map`
- 지도가 화면 전체(상단 띠 제외). 왼쪽 위 **아이콘 버튼 4개 세로**: 🔍 검색 · ⚑ 필터 · ◧ 레이어 · ≡ 범례. 각각 누르면 **패널 하나만** 펼쳐진다(MarineTraffic 툴바 방식).
  - 필터: 영향 H/M/L/정상/보류 체크 · 위협 1~5 · 메시지 종류 · 상태(항해 중 ≥ 0.5 kn / 정박) — 조합 가능. 필터 결과 배 수를 버튼에 작게.
  - 레이어: 수신 여유 등고선 · 환경 잔차 등고선 · 보고 밀도 · ENV_LOSS 비율 · 항적(선택 배) — 1차 체크 5개 그대로, 각 항목 옆 한 줄 설명.
  - 범례: 아이콘 색 6개 · 반투명 뜻 · 방향 미상 표시 뜻.
- 아래 가장자리 **시점 슬라이더**(얇은 띠, 시각 표시, ◀ ▶ 1분 이동, ▶ 재생 — 1차에 재생이 없으면 추가: 1초마다 1분).
- 배 클릭 → **오른쪽 카드가 미끄러져 나옴**(지도 위 겹침, 닫기 ×): MMSI · 등급 배지(H "즉시 확인") · 대표 코드 + 설명 · 속력/선수/침로(출처) · 마지막 보고 시각·경과 · 신호 원인 카드(송신기/해역/혼잡/미상 %) · 이 기간 비정상 비율 · "자세히 →" (`#/ship/<mmsi>`). 항적은 지도에.
- hover 이름표(MMSI·등급)는 1차 그대로.

### ③ 선박 목록 `#/ships` · 배 상세 `#/ship/<mmsi>`
- 목록: 전체 폭 표, 1차 열(MMSI·위협·영향·대표 코드·갈래·비정상 비율·마지막 보고·신호) 그대로 + 머리 클릭 정렬·검색·종류·상태 필터 그대로. 영향 배지는 "H 즉시 확인"처럼 **글자와 함께**. 행 클릭 → 상세.
- 상세(한 화면): 위에 요약 카드(②의 카드와 같은 내용) · 가운데 **작은 지도 + 항적** · **시간별 막대**(이 배의 판정: 시간대마다 정상/비정상/보류 행 수) · 메시지 종류별 건수 표 · 코드별 비정상 행 수 + 한 줄 설명 · 신호 원인 카드. "← 목록" 과 "지도에서 보기".

### ④ 수신 현황 `#/flow` (옛 토폴로지)
숫자는 1차 `/api/window` 의 토폴로지 집계 **그대로**(API 바꾸지 않음 — `check_topology_sum.py` 가 그대로 통과해야 한다). 그림만 바꾼다.
- 맨 위 한 문장: "수신소 1에 808,480건이 들어왔고 그중 **72.4%가 비정상**, 1.6%가 보류입니다."
- **막대 ①** 해안국별: 수신소마다 가로 막대 하나, 정상(회색)·비정상(빨강)·보류(분홍) 누적, 오른쪽에 건수·배 수. 캡션 "이 막대는 수신소가 받은 메시지 중 판정 결과의 비율입니다."
- **막대 ②** 메시지 종류별(AIS 위치 보고 · AIS 정적·기타 · ASM · VDE): 같은 누적 막대, VDE 는 "0건 — 자리만" 표시. 캡션 "어떤 종류의 메시지가 얼마나 들어오고, 종류마다 비정상 비율이 어떤지."
- **막대 ③** 위협별 배 수(1~5 + 보류): 가로 막대, 색 = 영향 등급. 캡션.
- 아래 **선박 상위 20** 표(1차 그대로). 막대 조각 클릭 = 1차 공유 필터 그대로(목록·지도에 반영).
- 선버스트·생키 코드와 `d3-sankey` 벤더는 **삭제**(VERSIONS.txt 갱신). d3 는 막대에 쓰거나 순수 DOM/CSS 로 그려도 된다.

### ⑤ 신호 품질 `#/signal`
- 위에 한 문장 + **원인 카드 4장**(송신기 약함 · 해역 환경 · 혼잡·간섭 · 미상 — 각 %, 한 줄 뜻, 기준값). 1차 cause 카드 내용.
- 아래 지도(등고선 2종 토글 + 보고 밀도 + ENV_LOSS) + 오른쪽에 **"왜 이렇게 그렸나"** 요약 10줄(감도 −107 dBm · 보호비 10 dB · 가림 문턱 −4 dB · 크리깅 · 생존 편향 주의) 과 `docs/SIGNAL_QUALITY_BASIS.md` 링크.

## 3. 선수 방향 기본 (요구 1)

코디네이터가 ml_all `scripts/datagen/build_risk_map.py` 에 `speed·heading·course` 열을 추가하고 `risk_map_real.parquet`·`risk_map_ds015.parquet` 을 **2026-10-27 다시 만들었다**(DB 값 그대로 — AIS 관례 HDG 511·COG 360·SOG 102.3 = "없음"). 작업 시작 때 `pq.ParquetFile(...).schema.names` 로 세 열이 있는지 먼저 확인하고, 없으면 멈추고 질문.

1. `coast/providers/parquet.py`: `BASE_COLS` 에 `heading`·`course`·`speed` 추가. risk_map 에 이미 있으면 `ml_table` 조인은 **하지 않는다**(있는 열만 조인, 없을 때만 폴백 — `speed_x/_y` 충돌 금지). 모듈 docstring·`sog_join` 메타 갱신.
2. 방향 우선순위(`ships_at`·`rotation.js` 공통, 지금 자리 그대로): **선수 HDG(0~359) → COG 데이터(0~359.9) → 항적 추정(30 m) → 그 배의 기간 안 마지막 유효 HDG/COG(출처 'last') → 없으면 북쪽(0°) 고정 + `dir_source='none'`**.
3. **원형 점을 없앤다.** 출처 'none' 배도 에셋으로 그리고(북쪽), 작은 "?" 표식이나 점선 테두리로 "방향 미상"을 표시. 툴팁·카드에 "선수 123° (HDG)" / "침로 98° (COG)" / "침로 45° (항적 추정)" / "방향 미상(북쪽 고정)" 로 출처를 쓴다. 범례에 넣는다.
4. 검사 `check_ships_at.py`: 시점 3개 × 소스 2 에서 API 의 heading/cog 가 parquet 의 마지막 위치 보고 값(511·360 제외)과 같은지, 우선순위대로 출처가 붙는지, **원형(방향 null) 배 0척**. `check_icon_rotation.js` 에 'last'·'none' 경우 추가. 실해역 시점 하나에서 **HDG 로 그려진 배 수 / COG / 항적 / last / none** 수를 CHANGES 에 표로.
